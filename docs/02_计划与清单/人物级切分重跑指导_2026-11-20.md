## 0. 为什么要重跑

主表用 `train_r` → `test_r`，切分依据是 `respondent_id`。但清洗表里的 `respondent_id` 是**逐年行号**：

| respondent_id | 2016 | 2018 | 2019 | 2020 |
|---|---|---|---|---|
| 0 | 1960 生 / 男 | 1986 / 女 | 1969 / 男 | 1992 / 女 |

`build_splits.py::_is_test_respondent` 对**这个行号**做 md5 取 20%。于是同一个人在不同年份有不同编号，各自独立地以 0.2 的概率进测试侧。一个在 4 个波次出现的人，**全部编号都落在测试侧的概率只有 0.2⁴ = 0.16%**；也就是说 99.84% 的人会以另一个编号出现在训练集里。

结论：现在的 `test_r` 不是 respondent-disjoint。要么改口径（已完成的 `held-out numbers` 写法），要么重建人物级 key 后重跑——本文是后者。

**不变量**：清洗口径、prompt 模板、模型、超参、GSS/FAS 全部不动。只换「谁是测试人物」的判定依据。

## 1. 先定验收标准

跑完必须能同时满足：

| # | 验收项 | 判定 |
|---|---|---|
| A1 | 人物级交集 | `person_id(train_r) ∩ person_id(test_r) = ∅` |
| A2 | 行级交集 | `orig_row_id(train_r) ∩ orig_row_id(test_r) = ∅` |
| A3 | 覆盖 | 人物链接覆盖率 ≥ 95%，冲突率 ≤ 1% |
| A4 | 主表可复算 | 同一批预测重算 `r_protocol_tables.py` 与论文表一致 |
| A5 | 泄漏量化 | 记录 v3→v4 的测试人物「在训练侧出现过的比例」从 ~99% 降到 0 |

达不到 A1–A3 就不要往下走，直接退方案 B（回退文档口径，见 §11）。

## 2. 阶段 0：定位原始个案编号（只读，约半天）

### 2.1 需要的文件

| 文件 | 位置 | 用途 |
|---|---|---|
| 合并特征表 | `/home/jpzhao_team/cyyuan/FAS_PRO/data/anes/processed/anes_all_years_with_features.csv` | 与清洗表对齐 `orig_row_id` |
| 六波原始包 | ANES 官方 2016 / 2018 / 2019 / 2020 / 2022 / 2024 | 取跨年一致的个案编号 |

原始包可能是 `.dta` / `.sav` / `.csv`，变量名各年不同，所以**先在每波里找「个案编号」候选列**，不要预设列名。

### 2.2 候选变量

按优先级找：`case_id`、`V160001`、`V200001`、`V240001`、`resp_id`、`panel_id`、`global_respondent_id`。

### 2.3 判定标准（三条同时满足才认）

1. **波内唯一**：`nunique == nrow`；
2. **跨年一致**：同一编号在不同波次的 `birthyr_resp` / `gender_resp` / `race_resp` 完全一致的比例 ≥ 99%；
3. **跨年有重叠**：同一编号出现在 ≥2 个波次的数量，与面板重叠规模相符（不是 0）。

三条只要有一条不满足，就换下一列。

### 2.4 只读排查脚本

```python
# python -m tools.probe_person_key（示例，不要写进 experiments/）
import pandas as pd, glob
from itertools import combinations

WAVES = {2016: "path/2016.*", 2018: "path/2018.*", 2019: "path/2019.*",
         2020: "path/2020.*", 2022: "path/2022.*", 2024: "path/2024.*"}

def load(p):
    return pd.read_stata(p) if p.endswith(".dta") else pd.read_csv(p)

frames = {y: load(glob.glob(p)[0]) for y, p in WAVES.items()}

CANDIDATES = ["case_id", "V160001", "V200001", "V240001", "resp_id", "panel_id"]
for col in CANDIDATES:
    rows = []
    for y, df in frames.items():
        if col not in df.columns:
            continue
        s = df[col]
        rows.append((y, len(df), s.nunique(), len(df) - s.nunique()))
    if rows:
        print(col, rows)
```

通过波内唯一后，再做跨年一致性：取 `birthyr` 所在列，按编号分组看 `nunique`。

## 3. 阶段 1：建 person 表与质量报告

### 3.1 归一化规则

- 去空格、统一大小写、数字补零到固定宽度；
- 字符串来源不同（如 `'0000123'` vs `123`）→ 先 `strip` 再尽量转 int，转不了就保留原样并记录；
- 不要跨来源直接比较裸字符串。

### 3.2 必须产出的三张表

| 表 | 内容 | 看什么 |
|---|---|---|
| `person_summary.csv` | 每个人物：波次数、行数、首末年份 | 跨波分布是否符合面板（不是全 0 也不是全 6） |
| `link_quality.csv` | 每人物的 `birthyr/gender/race` 一致率 | 冲突人物清单，抽样人工核对 |
| `wave_counts.csv` | 每波：行数、逐年编号数、人物数 | 人物数 ≤ 编号数，差异应可解释 |

### 3.3 失败处理

- 无法链接的个案 → `link_status = "unique"`（只在这一波出现），**保留但单独计数**；
- 冲突（同一编号跨年人口学不一致）→ `link_status = "conflict"`，**不参与切分**，在论文里报告占比；
- 冲突率 > 1% 或覆盖率 < 95% → 停下，回到 §2 换候选变量。

## 4. 阶段 2：重做切分（v4）

### 4.1 唯一要改的逻辑

`experiments/data/build_splits.py` 里的 `_is_test_respondent(rid)`：把入参从「逐年编号」换成「人物编号」。md5 → 20% 的分桶规则、抽样上限、`test_tr ⊂ test_r` 全部保持不变。

### 4.2 构造顺序（顺序错了会重新引入泄漏）

1. `pool` = 采样训练文件命中的行（`TRAIN_SOURCE`）∩ 2016–2020；
2. 计算 `pool.person_id`；
3. **先**算出测试人物集合 `test_persons`（按 `person_id` 哈希 20%）；
4. `train_r = pool[~pool.person_id.isin(test_persons)]`；
5. `test_r` 从「全部年份、`person_id ∈ test_persons`」的行里按**人物整组**抽到 6,000 行；
6. `test_tr = test_r[year == 2024]`。

注意第 4 步：不是「先取 train_t 再按编号筛」，而是**先剔除整个测试人物**。否则同一个人在训练年份的行会漏进 `train_r`。

### 4.3 输出位置

```
data/anes/v4/splits/{train_r,test_r,test_tr}.jsonl
data/anes/v4/splits/manifest.json
```

`v3` 保留不动，便于对比与回退。

### 4.4 断言（写进脚本，跑不过就退出）

```python
assert set(train_r.person_id) & set(test_r.person_id) == set()
assert not (set(train_r.orig_row_id) & set(test_r.orig_row_id))
assert set(test_tr.orig_row_id) <= set(test_r.orig_row_id)
assert test_t.candidate.unique().tolist() == ["biden", "trump"]   # 2024 仍只有两人
```

### 4.5 与 v3 的差异表（拿给导师看的第一张表）

| 指标 | v3（编号切分） | v4（人物切分） |
|---|---|---|
| train_r 行数 / 人物数 | 5,094 / 2,131 编号 | 待测 |
| test_r 行数 / 人物数 | 6,014 / 192 编号 | 待测 |
| test_r 2016–2019 行数 | 2,726 | 待测 |
| strict T×R 行数 | 226 | 待测 |
| 测试人物在训练侧出现过的比例 | **~99%**（估算） | **0%** |

## 11. 风险与回退

| 风险 | 处理 |
|---|---|
| 找不到跨年一致的个案编号 | 退方案 B：论文保留 `held-out numbers` 写法，汇报口头用「编号留出」 |
| 原始包拿不到（只有合并表） | 同 B；并在 Limitations 写明「人物级隔离未验证」 |
| 冲突率 > 1% | 只保留 linked 子集，在论文报告覆盖率，不混入 conflict |
| 重跑后指标明显下降 | **如实报告**，并把 v3/v4 差异写成「编号切分的泄漏量化」，这是贡献不是事故 |
| GPU 时间不够 | 先跑 1 seed 看方向，方向不稳再等 3 seeds |
