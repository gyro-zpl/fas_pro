## 0. 一句话总结

第一轮修改是有效的：RQ1–RQ3、"boundary study"框架、预训练污染、FAS generation setup、消融措辞、FAS bootstrap CI、DeepSeek 第二模型都已补上。  
但第二轮把论文数字逐项对回代码与 `preds/` 后，发现论文目前的三个"卖点"里，有两个需要重写口径：

1. **个体级**：论文写的是"unseen respondents / respondent-disjoint"，但实际训练用的是 `train_t`，`test_r` 的 192 名受访者中有 170 名在训练池里出现过（这 170 人贡献了 91.4% 的 in-distribution 行）；`train_r` 的训练脚本存在，但从未跑过。
2. **群体级**：FAS 没有报告最直接的基线——直接从重建联合分布 $Q^\*$ 采样。补算后，**prior-only 在 EDC/EHC 的 marginal 与 joint JS 上都优于最好的 LLM 运行**（joint CI 不重叠），因此"fine-tuning 把 JS 降低 91%/86%"只是相对 base LLM 成立，不能支撑"LLM 能对齐群体分布"的结论。
3. **choice 指标**：0.518 不是 3-seed 的逐 seed 均值，而是把 3 个 seed 的预测拼在一起后按行 `idxmax` 的结果；顺序打乱后会在 0.404–0.450 之间漂移。逐 seed 均值是 **0.553 ± 0.011**，tie-aware 约 **0.510**。论文自己的消融表用的就是 0.553，前后不一致；与 GBM/DeepSeek 的 choice 比较方向也会改变。

这些问题不否定论文的价值：**2024 时间塌缩**仍是全文最扎实、最有价值的负面结果；个体级"competitive, not superior"在修正口径后仍然成立；数据审计仍然是有用的方法贡献。问题集中在"论文声称的贡献 > 数据能支持的贡献"，需要一次定向重写，而不是推倒重来。

### P0-1 "Unseen respondents / respondent-disjoint" 与实际训练设置不符（Critical）

**论文原话**

- Conclusion（`thesis/chapters/05_conclusion.tex:54`）："On unseen respondents in the same era..."

**实际训练/评测设置**

| 检查 | 数值 | 来源 |
|---|---|---|
| 主模型训练集 | `train_t`（2016–2020，6,516 行，2,720 名受访者） | `experiments/run_train_seeds.sh:16`、`data/anes/v3/splits/manifest.json` |
| 主模型名称 | `qwen3_8b_t_seed42/43/44` | `sft/sft_models/`、`experiments/runs.csv` |
| `test_r` 受访者 | 192 名 | `manifest.json` |
| 其中在 `train_t` 出现过 | **170 名（88.5%）** | 本次复核，按 `respondent_id` 交集 |
| in-dist（2016/2018/2019）行数 | 2,726 | `manifest.json` |
| 其中来自"训练中见过"的受访者 | **2,492 行（91.4%）** | 本次复核 |

| `train_r` 模型 | `run_train_r_seeds.sh` 存在，但 `sft/sft_models/` 中**没有** `qwen3_8b_r_seed*`；所有评测都用 `qwen3_8b_t_seed*` | `experiments/run_train_r_seeds.sh`、`sft/sft_models/` |

**为什么严重**

- 论文的 R 协议设计是"按受访者 80/20 划分，训练集 `train_r` 与测试集 `test_r` 受访者不重叠"。这个设计在 split 层面成立（`manifest.json` 的 `train_r_test_r_respondent_overlap = 0`），但**主模型从来没有在 `train_r` 上训练过**。实际评测的是 `train_t` 模型，它见过 88.5% 的 `test_r` 受访者的其他行。
- 于是"unseen respondents"不成立，实际是"seen respondents 的 held-out rows"。LLM 可能记住同一受访者的评分风格/尺度使用；GBM 的特征里没有 respondent id，无法利用这一点。**如果 LLM 利用了这一点，偏差方向有利于 LLM**，因此不能把"持平"解释为 LLM 在没有受访者信息条件下的竞争力；至少它不再是一个干净的 respondent-disjoint 比较。
- 这不是措辞小问题：它是贡献 1（"two protocols ... respect the ANES panel"）和贡献 2（"on unseen respondents"）的核心。答辩时只要老师问一句"你的 test 受访者有没有在训练集里出现过"，就会暴露。

**建议（三选一，按优先级）**

- **A（推荐，若算力允许）**：跑 `bash experiments/run_train_r_seeds.sh`（3 seeds，约 45–60 分钟/seed），在 `train_r` 上重训 HistGB/Ridge（分钟级），然后用 `test_r` 重新评测。这样 R 协议才真正 respondent-disjoint。主表、Abstract、Intro、Results、Conclusion、Appendix D 的数字都要更新；T 协议（2024）继续用 `train_t` 模型，两者分工明确。
- **B（最低限度）**：把 R 协议改称 "held-out-row protocol" / "item-level holdout"，删除所有 "unseen respondents" / "respondent-disjoint" 表述；在 Limitations 明确写出 170/192、2,492/2,726、1,543/1,712 这三组重叠数字。贡献从"generalization to unseen individuals"降为"held-out rating prediction on panel respondents"。诚实，但贡献变弱。
- **C（最稳）**：A + B 都做。主结果用 `train_t` 的 held-out rows（与 2024 时间分析同一模型），另加一个 `train_r` 的 respondent-disjoint replication 作为稳健性检查，放 Appendix。这样既不丢现有结果，又补上真正的 respondent-disjoint 证据。

**需要同步修改的位置**：`main.tex:80`、`01_intro.tex:38`、`02_method.tex:30-36`、`03_results.tex:6-7`、`table2_pas.tex:4`、`05_conclusion.tex:54`、`appendix/B_results.tex:9`、`docs/04_论文稿件/初稿_2026-11-09.md` 对应段落、`doc_latex/body_final.tex` 对应段落。

### P0-2 Choice 0.518 是池化/并列伪影；主结果应为 0.553 ± 0.011（Critical）

**论文原话**

- Abstract（`main.tex:82-83`）："choice accuracy of 0.518 against a chance level of 0.163."
- Intro（`01_intro.tex:39-40`）：同 0.518。
- Results（`03_results.tex:14`）："choice accuracy of 0.518 [0.481, 0.552]."
- Table 3.1（`table2_pas.tex:10`）：Fine-tuned LLM 0.518。
- Conclusion（`05_conclusion.tex:56`）：0.518。
- Appendix D（`D_second_family.tex:22-23`）：Qwen 0.518，DeepSeek 0.548，并写"the DeepSeek model has a slightly higher choice accuracy."

**重算结果（从 `experiments/results/preds/` 原始预测）**

| 计算方式 | seed42 | seed43 | seed44 | 均值 |
|---|---|---|---|---|
| 逐 seed `idxmax` choice | 0.5598 | 0.5383 | 0.5622 | **0.553 ± 0.011** |
| 3-seed 拼接后 `idxmax`（论文 0.518 的来源） | — | — | — | **0.519**（点估计；bootstrap 均值 0.518；顺序打乱后在 0.404–0.450 漂移） |
| tie-aware exact choice（并列按比例给分） | 0.5098 | 0.5155 | 0.5093 | **0.511** |
| HistGB（tie-aware / idxmax） | — | — | — | **0.546 / 0.534** |

**为什么会这样**

- `bootstrap_main.py` 把 3 个 seed 的预测 `pd.concat` 后，按 `(respondent_id, year)` 分组做 `idxmax`。每个组现在有 2 个候选人 × 3 个 seed = 6 行，`idxmax` 会在 6 行里挑一个；真实 choice 也在 3 份重复的 true score 里挑。**并列时的行顺序决定结果**。把拼接后的行随机打乱，choice 在 0.404–0.450 之间变化，证明 0.519 不是模型性能，而是排序/并列伪影。
- 逐 seed 的 choice 是 0.538–0.562，均值 0.553，与消融表（`appendix/B_results.tex:39`，0.553 ± 0.011）一致。论文自己在 Results（`04_temporal.tex:53`）也用了 0.553，读者会看到同一个模型两个 choice 值。
- 另外，418 个 respondent–year 组里有 **193 组（46%）预测 argmax 并列**，53 组真实 argmax 并列。LLM 输出整数评分，GBM 输出连续值，`idxmax` 对 LLM 的并列处理会系统性地影响比较。

**影响**

- 主表的 0.518 vs HistGB 0.534 会让 LLM 看起来在 choice 上略低；逐 seed 均值 0.553 vs 0.534 则略高。两者都不显著（paired bootstrap Δchoice +0.026 [−0.007, +0.062]），所以"no significant difference"仍然成立，但**点估计方向和大小都变了**。
- Appendix D 的"DeepSeek 0.548 > Qwen 0.518"在修正后变成 "Qwen 0.553 > DeepSeek 0.548"；三指标（MAE、corr、choice）都变成 Qwen 略优，"DeepSeek 略高 choice"的句子必须删掉。
- tie-aware 下 LLM 0.511 vs GBM 0.546，Δ = **−0.036 [−0.077, +0.005]**；即使用最保守的指标，"no significant difference"仍成立，但不能再写 LLM 的 choice 点估计高于 GBM。

**建议**

1. 主表改为**逐 seed 均值 ± std**：0.553 ± 0.011；如果要保留 CI，用 respondent–year 组的 cluster bootstrap（逐 seed 算 choice，再平均），不要拼接 3 个 seed。
2. 在 Metrics 或 Appendix 加一段 "tie handling"：说明 LLM 输出整数、并列常见；报告 tie-aware exact 和 pairwise ranking accuracy 作为稳健性检查。
3. 更新所有 0.518 出现的位置（Abstract、Intro、Results、Conclusion、Table 3.1、Appendix D、ACL 版），并修正 DeepSeek 比较。
4. 消融表的 0.553 与主表统一；在表注说明 Full 的 choice 是 3-seed 均值，A1–A3 是单 seed。
5. 如果保留 paired bootstrap 的 +0.026，明确它是 seed42 的 idxmax 结果；同时给出 tie-aware 的 −0.036 [−0.077, +0.005]，让读者看到指标敏感性。

### P0-3 FAS 缺少 prior-only 基线；补算后该基线优于 LLM（Critical）

**问题**

FAS 的 pipeline 是：用 2004–2022 的历史 GSS 外推 + IPF 重建 2024 的联合分布 $Q^\*$，再从 $Q^\*$ 采样生成 SFT 数据，最后比较 base/SFT 生成的 400 行与 2024 经验分布。  
论文只比较了 **base LLM vs SFT LLM vs RAG/quota**，没有报告最直接的基线：**直接从 $Q^\*$ 采样 400 行**（不用 LLM）。  
这不是可选的"nice-to-have"：$Q^\*$ 是作者自己构建的、SFT 数据的来源；如果 $Q^\*$ 本身就能很好地匹配 2024，那么"fine-tuning 降低 JS"只说明 LLM 在向 $Q^\*$ 靠近，不能说明 LLM 有群体级对齐能力。

**补算结果**（`docs/03_进度与执行/prior_baseline_check.py`，400 行，seed 42，1,000 次行 bootstrap）

| Run | EDC marginal JS [95% CI] | EDC joint JS [95% CI] | EHC marginal JS [95% CI] | EHC joint JS [95% CI] |
|---|---|---|---|---|
| **IPF prior（无 LLM）** | **0.0004 [0.0002, 0.0023]** | **0.0076 [0.0070, 0.0141]** | **0.0011 [0.0006, 0.0036]** | **0.0225 [0.0192, 0.0308]** |
| LLM SFT-v3（最好 LLM） | 0.0040 [0.0022, 0.0077] | 0.0215 [0.0181, 0.0305] | 0.0077 [0.0052, 0.0123] | 0.0363 [0.0332, 0.0458] |
| LLM direct SFT | 0.0048 [0.0029, 0.0089] | 0.0160 [0.0139, 0.0247] | 0.0167 [0.0130, 0.0229] | 0.0470 [0.0413, 0.0587] |
| base LLM | 0.0552 | 0.1181 | 0.0319 | 0.1001 |

- prior-only 在 **EDC/EHC 的 marginal 和 joint 上都优于所有 LLM 条件**；joint 的 95% CI 与 v3 不重叠（EDC 0.0141 < 0.0181；EHC 0.0308 < 0.0332）。EHC marginal CI 也不重叠（0.0036 < 0.0052）；EDC marginal 的 CI 上界 0.0023 与 v3 下界 0.0022 基本相接。
- 用 800 次、三张 pairwise 表的 `ipf_with_tables` 变体重算，结果在 4 位小数上相同（0.0004/0.0076、0.0011/0.0225），说明这个结论对 IPF 的具体实现稳健。
- 论文原话"including the pairwise structure that a marginal-only sampler would miss"（`docs/04_论文稿件/初稿_2026-11-09.md:278`）是稻草人：正确的对照不是 marginal-only sampler，而是从 $Q^\*$ 采样的 joint sampler；后者恰恰更好。

**为什么严重**

- 论文的群体级贡献（Contribution 3、Abstract 的 91%/86%、Conclusion 的 "population-level result is stronger for EDC"）是建立在"LLM 能对齐群体分布"上的。补算表明：**在这个无条件分布匹配任务上，经典 prior 更好，LLM 是多余的一步**。SFT 确实把 LLM 从 base 拉向 $Q^\*$，但它没有超过 $Q^\*$。
- 这不意味着 FAS 工程没价值：LLM 的潜在价值在**条件生成/自然语言控制/子群分析/场景扰动**，但这些任务在训练 mixture 里有，却**没有单独评测**。论文当前评测的是最容易输给 prior 的那个任务。
- 答辩时最可能被问："既然 IPF 采样就能做到 0.0004/0.0076，为什么还要 LLM？" 目前论文没有答案。

**建议**

1. **必须**在 Table 3.2 / Appendix C 加一行 "IPF prior (no LLM)"，并如实写出上述数字。
2. 重写群体级叙事，三选一：
   - **A. 负结果/边界**：明确写"在无条件分布匹配上，prior-only 优于 LLM；结构化对齐让 LLM 接近 prior，但没有超过它。LLM 的价值需要条件任务来证明。" 这与论文的 boundary study 框架一致，且诚实。
   - **B. 条件任务**：补一个条件评测（例如给定子群/场景/自然语言约束，比较 LLM 与 prior 的条件分布）。如果 LLM 在条件任务上更好，FAS 贡献可以保留，但主张要从"分布对齐"改成"条件生成"。
   - **C. 重新定位 FAS**：把 FAS 章节从"LLM 的群体级能力"改为"一个可复现的 prior 构建 + LLM 采样管线"，并明确 LLM 不是分布匹配的必要组件。这会削弱贡献 3，但保住论文的诚实性。
3. Abstract、Intro 贡献 3、Results 3.2、Conclusion 都要同步；ACL 版同样。
4. 如果暂时不补条件任务，至少不要把 "fine-tuning reduces JS by 91%" 写成"LLM 能对齐群体分布"；改成"fine-tuning moves the LLM toward the reconstructed prior; the prior itself remains the stronger distributional baseline."

### P0-4 FAS 方法描述与实际代码不一致（Critical / 可复现性）

**论文原话**（`thesis/chapters/02_method.tex:55-65`）

> "every univariate and pairwise cell is extrapolated with a four-model ensemble ... The predicted marginals and pairwise tables are combined with iterative proportional fitting ... multiplicative updates match each pairwise table and marginal, run for 800 iterations, and are normalized with Laplace smoothing."

**实际代码**

- `sft/teacher_distribution/get_distribution.py:93,286,420`：
  `Q_joint = ipf_joint(P_a_0, P_b_adj, P_c_0, P_bc_0, iters=300)`。
- `ipf_joint`（同文件 255–289 行）只匹配 **$P_{B,C}$ 和 $P_A$**，不匹配 $P_{A,B}$、$P_{A,C}$，也不匹配 $P_B$、$P_C$ 的独立约束；迭代 **300** 次。
- `sft/teacher_distribution/make_finetune_datasets.py:408`：
  `# Q_2024 = ipf_with_tables(... iters=800)` —— **被注释掉了**。
- `initialize_distributions_from_real_data`（同文件 105–130 行）用的是 `get_distributions_for_attrs` 返回的 `Q_joint`，即上面的 300 次、双约束版本。
- `ipf_with_tables`（800 次、三张 pairwise 表）只在 `quota_annealing_system.py:647` 里被调用，用于 quota 条件，不是 SFT 数据的生成路径。

**结论**

- 论文把"所有 pairwise 表 + 800 次"写成了 SFT 数据的重建方法，但实际是"marginals + $P_{B,C}$ + 300 次"。
- 两种方法在我补算的 prior 基线里数值几乎一致（4 位小数），所以**结果本身不必重跑**；但方法章节必须改成实际代码路径，否则是可复现性/准确性问题。
- 如果作者想保留"800 次、全 pairwise"的表述，就必须用 `ipf_with_tables` 重新生成 SFT 数据并重训 GSS 模型；这是更大的工程，不推荐在提交前做。

### P1-1 FAS headline 用 91%/86%，但"最干净"的是 v3 的 93%/82%；coverage-adjusted 后 direct SFT 只剩 32%/59%

### 8.2 choice 重算

```bash
python - <<'EOF'
import pandas as pd, numpy as np, glob
files = sorted(glob.glob('experiments/results/preds/qwen3_t_seed*_test_r_generate.predictions.jsonl'))
frames = [pd.read_json(f, lines=True) for f in files]
def choice(df):
    c = g = 0
    for _, gg in df.groupby(['respondent_id','year']):
        if len(gg) < 2: continue
        t = gg.loc[gg.true_score.idxmax()]; p = gg.loc[gg.pred.idxmax()]
        c += int(t.name == p.name); g += 1
    return c/g
for f in frames:
```
