# 人物级链接审计（2026-11-20）

> 目的：验证 v4 人物级切分（[重跑指导](../02_计划与清单/人物级切分重跑指导_2026-11-20.md)）能否从现有 ANES 文件建立跨年 person key。
> 结论：**不能**。原始 CSV 的 `caseid` 也是波内 1..N 编号，processed 表的 `respondent_id` 是 0..N−1；跨年人口学一致率接近随机。v4 重训不可识别，按指南 **fallback B** 处理。

## 2. 跨年 `caseid` 检查

如果 `caseid` 是跨年 person ID，同一个 ID 在不同波次应有相同的出生年和性别。实际结果：

| 年份对 | ID 交集 | 出生年一致率 | 性别一致率 |
|---|---:|---:|---:|
| 2016–2018 | 1,092 | 1.7% | 49.4% |
| 2016–2019 | 1,200 | 2.6% | 51.7% |
| 2018–2019 | 2,500 | 2.0% | 51.3% |
| 2019–2022 | 1,585 | 1.8% | 48.0% |
| 2019–2024 | 1,909 | 1.2% | 0.0% |
| 2022–2024 | 1,585 | 1.6% | 0.0% |

一致率接近随机（出生年约 1–3%，性别约 50% 或 0%），说明**同一个 `caseid` 在不同波次是不同的人**。`caseid` 不是 person key。

## 3. Processed 分析表

`data/anes/v3/anes_candidates_clean.csv` 的 `respondent_id` 是每波 0..N−1 的行号；跨年数字重叠同样没有人口学一致性（出生年 0–2.6%，性别 0–52%）。因此：

- `train_r`/`test_r` 是**数字层面**的 80/20 切分，不是人物层面；
- 同一个人可以在 2016 的 `train_r` 和 2018 的 `test_r` 里以不同数字出现；
- 现有文件无法测量或消除这种 person-level 泄漏。

## 4. v3 切分的数字重叠（不是人物泄漏）

| 协议 | train | test 数字在 train 出现 | test 行来自这些数字 | in-dist 行 / 其中来自这些数字 |
|---|---|---:|---:|---:|
| R（`train_r` → `test_r`） | 5,094 行 / 2,131 数字 | **0** | **0** | 2,726 / **0** |
| T（`train_t` → `test_r`） | 6,516 行 / 2,720 数字 | 170 | 5,443 | 2,726 / 2,492 |

R 的 0 重叠是切分构造的结果，证明的是 **held-out respondent numbers**，不是人物隔离。T 的 170/192 数字重叠是时间协议的设计（T 模型本来就在所有受访者的早期波次上训练），也不能解释为人物泄漏。

## 5. 结论与建议

1. **v4 人物级重训不可识别**：现有原始 CSV 和 processed 表都没有跨年 person key；2020 只有随机 `ResponseId`。指南 §11 的 fallback B 适用。
2. **论文口径**：统一为 “held-out respondent numbers within a wave”；不要写 “unseen respondents” 或 “respondent-disjoint”。在 Limitations 明确：分析表只有波内编号；person-level isolation 未验证；原始 ANES panel identifiers 不在发布文件中。thesis Appendix A 的 “Person-Linkage Audit” 给出六波 ID 范围、跨年一致率和 R/T 重叠表。
3. **如果拿到原始 `.dta`/`.sav`**（含 `V160001`/`V200001`/`V240001` 等稳定个案号），可以按指南 §2–§7 重跑 v4；在此之前不训练 v4，避免把“数字切分”包装成“人物切分”。
